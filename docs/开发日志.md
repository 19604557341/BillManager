### 技术决策与踩坑
- **修复统计接口 `categoryName` 为 null 的 bug**：分类汇总 SQL 的 JOIN 条件硬编码 `c.status = 1`，状态码约定翻转后 1 变成了「禁用」，LEFT JOIN 一条都关联不上（金额不受影响，因为 LEFT JOIN 保留了账单行）。已改为 `c.status = 0`。教训：**手写 SQL 里的魔法值不会跟随枚举重构**，翻转约定后必须全局搜索 `status = 1` / `status=1` 之类的硬编码逐一核对。
- **`selectList` 无记录时返回空列表而非 null**：`deleteCategory` 的物理删除分支最初写成 `if (billList == null)`，永远不会命中，导致所有分类（包括没有账单的）都被禁用。已改为 `billList.isEmpty()`。
- **GET + `@RequestBody` 的兼容性问题被文档工具放大**：接入 Swagger UI 后发现 GET 请求体参数无法正常展示与调试，顺势改为 Query String 绑定 DTO，行为对现有前端也更友好。

## 2026-09-25 账单统计模块与枚举改造收尾

### 完成内容
- 新增账单统计接口 [`BillStatisticsController`](../src/main/java/com/example/billmanager/controller/BillStatisticsController.java)：
  - `GET /api/bills/statistics`：按「日期范围 + 账单类型」一次返回三组数据——总收入 / 总支出 / 结余、按分类汇总金额与占比（饼图）、按日 / 按月的收支趋势（折线图）。
  - 查询参数 [`BillStatisticsDTO`](../src/main/java/com/example/billmanager/dto/amount/BillStatisticsDTO.java)：`startDate` / `endDate` / `billType` 必填，`groupBy` 默认 `"day"`、传 `"month"` 按月分组。
  - 统计服务 [`BillStatisticsService`](../src/main/java/com/example/billmanager/service/BillStatisticsService.java)：执行三个聚合查询后在内存中完成派生计算（结余、占比、按日补零），组装为 [`BillStatisticsVO`](../src/main/java/com/example/billmanager/vo/amount/BillStatisticsVO.java) 返回。
  - [`BillMapper`](../src/main/java/com/example/billmanager/mapper/BillMapper.java) 新增三个 `@Select` 聚合 SQL（总额 / 分类金额 / 收支趋势），均带 `deleted = 0` 逻辑删除过滤与 `COALESCE` 空值兜底。
  - 新增 `dto/amount/` 4 个查询结果 DTO 与 `vo/amount/` 3 个响应 VO，全部补充中文注释。
- 枚举改造收尾（TD-12 的 DTO 部分）：`BillCreatedDTO`、`BillUpdateDTO`、`BillQueryDTO` 的 `billType` 由 `String` 改为 `BillType` 枚举，删除 `BillServiceImpl.parseBillType()` 字符串转枚举的兜底方法。
- [`GlobalExceptionHandler`](../src/main/java/com/example/billmanager/exception/GlobalExceptionHandler.java) 新增 `HttpMessageNotReadableException` 处理（TD-7 部分解决）：枚举非法值、请求体格式错误统一返回 400 自定义提示，不再暴露后端默认报错。

### 技术决策与踩坑
- **枚举非法值根本走不到 JSR-303 校验**：`billType` 改为枚举后，前端传非法值时失败发生在 Jackson 反序列化阶段（DTO 对象尚未构建成功），抛出的是 `HttpMessageNotReadableException` 而非 `MethodArgumentNotValidException`；未专门处理时 Spring 会把默认错误响应（含内部类名等信息）直接返回给前端——这就是 Apifox 实测"返回的不是自定义格式"的根因。另注意 `@Pattern` 只对 `String` 生效，对枚举字段永远不会触发。现由全局异常处理器统一返回「参数 billType 取值无效：XXX，只允许：INCOME、EXPENSE」。
- **Spring Boot 4 默认 Jackson 3，包名与 API 均与 Jackson 2 不同**：异常类在 `tools.jackson.databind`（而非 `com.fasterxml.jackson.databind`），`Reference.getFieldName()` 已改名 `getPropertyName()`。两处均实际编译报错，最终用 `javap` 反编译本地仓库 jar 确认方法签名后修正。
- **趋势按日补零放在服务层**：SQL `GROUP BY` 只返回有账单的日期，直接返回会导致折线图 X 轴断档；服务层从开始日期到结束日期逐天生成完整序列，无账单日期收入 / 支出 / 结余补 0。按月分组因跨度不确定不补零。
- **占比计算防无限小数与除零**：先以 4 位小数精度做除法（`HALF_UP`）再乘 100，最后保留 2 位小数——直接除法遇无限循环小数会抛 `ArithmeticException`；所有分类合计为 0 时占比直接置 0。副作用：各分类分别四舍五入，占比合计可能为 99.99% 而非严格 100%，属展示精度误差。
- **LEFT JOIN 只关联启用分类、但不丢账单**：分类汇总 SQL 用 `LEFT JOIN category ... AND c.status = 1`，分类被禁用或删除后对应账单金额仍计入统计，仅分类名为 null。
- **统计接口使用 GET + `@RequestBody`**：查询条件较复杂故走 JSON 请求体，要求客户端支持 GET 携带请求体（Apifox / axios 均可）。

## 2026-09-23 账单模块（删除）

### 完成内容
- 删除账单接口 [`BillController.deleteBill()`](../src/main/java/com/example/billmanager/controller/BillController.java)：
  - `DELETE /api/bills/{billId}`：路径参数定位待删除账单，`@NotNull` 校验路径参数，账单不存在时由全局异常处理器统一返回错误响应。
  - 业务实现 [`BillServiceImpl.deleteBillById()`](../src/main/java/com/example/billmanager/service/impl/BillServiceImpl.java)：
    - 先查询账单存在性，不存在时抛出 404 业务异常。
    - 基于 `@TableLogic` 执行逻辑删除，MyBatis-Plus 自动将删除转换为 `UPDATE bill SET deleted = 1`，数据库记录保留，后续查询自动过滤已删除账单。
    - 检查 `deleteById` 返回的受影响行数，行数为 0（账单已被并发删除）时同样抛出 404 业务异常。

### 技术决策与问题解决
- **修复注释与实际行为不符的关键问题**：原 Service 接口与实现的注释写的是"执行物理删除""删除操作不可恢复"，但 [`Bill`](../src/main/java/com/example/billmanager/entity/Bill.java) 实体的 `deleted` 字段标注了 `@TableLogic`，实际执行的是逻辑删除；已修正 Controller / Service / ServiceImpl 三层的相关注释，避免误导后续维护者。
- **并发竞态防护**：原实现先 `selectById` 再 `deleteById`，两步之间账单可能被其他请求并发删除，此时删除影响行数为 0 但接口仍返回"删除成功"的假象；现通过检查受影响行数兜底，行数为 0 时按 404 处理。
- **清理 Service 接口层无效校验注解**：`BillService.deleteBillById()` 参数上的 `@NotNull` 不会生效（方法级校验需要实现类标注 `@Validated`，而 `BillServiceImpl` 未标注），且控制层已做同样校验，属于冗余误导；已移除该注解及对应导入。

- **提前在业务层校验分类**：若直接落库，无效分类 ID 会触发数据库外键约束异常（表现为 500 系统错误）；提前校验可返回语义明确的业务错误提示（404/400）。

  - 结果按账单日期、创建时间倒序排列。

### 技术决策与问题解决
- **分页插件**：在 [`MyBatisPlusConfig`](../src/main/java/com/example/billmanager/config/MyBatisPlusConfig.java) 中注册 `PaginationInnerInterceptor`（MySQL 方言），并设置单页最大条数 `maxLimit=100` 与 DTO 校验保持一致，防止恶意超大分页请求。
  - 踩坑记录：缺少分页拦截器时 `selectPage` 不会生成 LIMIT 子句，会查出全表数据且 `total` 恒为 0。
- **方法级参数校验异常**：Spring Framework 6.1+ 中，`@Validated` 类的 `@PathVariable` / `@RequestParam` 简单参数校验失败时抛出的是 `HandlerMethodValidationException` 而非 `ConstraintViolationException`，已在 [`GlobalExceptionHandler`](../src/main/java/com/example/billmanager/exception/GlobalExceptionHandler.java) 中单独处理。

  - 字段自动填充 [`MyMetaObjectHandler`](../src/main/java/com/example/billmanager/config/MyMetaObjectHandler.java)：插入时填充 `createdTime` / `updateTime`，更新时填充 `updateTime`。

### 技术决策与问题解决
- **分类删除采用"禁用"而非物理删除**：账单表通过外键引用分类，物理删除会破坏历史账单数据；同时数据库唯一索引 `(category_name, category_type)` 会被已禁用分类占用。
- **禁用分类的重建策略**：新增分类时若发现同名同类型分类已存在——
  - 处于启用状态 → 抛出 409 业务异常"该分类已存在"；
  - 处于禁用状态 → 恢复启用并更新排序值，规避唯一索引冲突（见 [`CategoryServiceImpl.createCategory()`](../src/main/java/com/example/billmanager/service/impl/CategoryServiceImpl.java)）。
